# WebPoB Architecture

## 1. Design Goals

WebPoB is a clean-room, pure-TypeScript port of [PathOfBuildingCommunity/PathOfBuilding](https://github.com/PathOfBuildingCommunity/PathOfBuilding) (PoE 1) and [PathOfBuildingCommunity/PathOfBuilding-PoE2](https://github.com/PathOfBuildingCommunity/PathOfBuilding-PoE2) (PoE 2) targeting the modern web browser.

### Core Architectural Decisions

1. **Pure TypeScript Monorepo**:
   - Every core layer (`@webpob/core`, `@webpob/i18n`, `@webpob/data`, `@webpob/codec`, `@webpob/calc`) has zero DOM/React dependencies and runs identically in browsers, Web Workers, and Node.js (Vitest).
2. **Dual-Game Ruleset Abstraction (`poe1` | `poe2`)**:
   - Rather than hardcoding `if (poe2)` everywhere, game-specific constants and formulas live in `GameRuleset`:
     - Base life/mana/spirit per level, attribute scaling (`Str -> Life/Melee Phys`, `Dex -> Accuracy/Evasion`, `Int -> Mana/ES` in PoE 1 vs PoE 2 rules where Str gives +2 Life/pt, Dex gives Accuracy, Int gives +2 Mana/pt, etc.)
     - Default resistance cap (75%) and endgame resistance penalty (-60% in PoE 1 Act 10 / -40% to -60% configurable in PoE 2)
     - Armour formula coefficient (`5 * damage` in PoE 1, `12 * damage` in PoE 2)
     - Slot definitions (PoE 1: 5 Flasks + item-linked gems; PoE 2: Life/Mana Flasks + Charms + Weapon Set 1/2 split passives + Spirit pool + unlinked skill gem groups)
3. **Canonical Bilingual Data & Normalization**:
   - All internal identifiers (`nodeId`, `gemId`, `mod.name`, `slotId`) are language-agnostic canonical IDs.
   - Text displayed to the user uses `LocalizedText` (`{ en: string; zh: string }`) or the `@webpob/i18n` translator.
   - User-entered text (pasted items from Chinese or English clients, custom modifier lines) passes through `@webpob/i18n`'s `normalizeStatLineToEn()` before entering `ModParser`, ensuring identical calculation accuracy regardless of client language.
4. **PoB Calculation Pipeline (`@webpob/calc`)**:
   - Mirrors Path of Building's proven architecture:
     1. **`ModDB` / `ModList`**: Stores typed modifiers (`BASE`, `INC`, `MORE`, `OVERRIDE`, `FLAG`, `LIST`) with `ModFlag` bitmasks (Attack, Spell, Hit, Melee, Projectile, Area, etc.), `KeywordFlag` bitmasks (Fire, Cold, Lightning, Chaos, Physical, Aura, Minion, etc.), and condition evaluators.
     2. **`ModParser`**: Converts canonical stat strings (e.g., `"+85 to maximum Life"`, `"30% increased Fire Damage"`, `"25% more Spell Damage"`, `"+38% to Fire Resistance"`) into `Mod[]` with source attribution.
     3. **`CalcSetup`**: Assembles the active `ModDB` from character level/class, allocated passive tree nodes (respecting active PoE 2 Weapon Set), equipped items (including local vs. global weapon/armour stat resolution), active skill + enabled supports, and configuration toggles (charges, buffs, custom mods).
     4. **`CalcDefence`**: Computes Attributes, Life, Energy Shield, Mana, Spirit (PoE 2), Armour & Physical Damage Reduction, Evasion Chance, Resistances (fire/cold/lightning/chaos with max cap & overcap), Block, Spell Suppression (PoE 1), and Effective Hit Pool (EHP).
     5. **`CalcOffence`**: Computes main skill base damage (weapon or spell gem), added damage effectiveness, damage conversion & gained-as-extra, increased/more multipliers, crit chance & crit multi, attack/cast rate, hit chance (accuracy vs enemy evasion), enemy resistance mitigation, and total Hit / DPS with full breakdown.
     6. **`computeNodePower`**: Clones build state with a candidate passive node toggled (allocate or deallocate) and computes `ΔDPS`, `ΔLife`, `ΔES`, and `ΔEHP` for live hover tooltips on the Passive Skill Tree.
5. **PoB Build Code Interoperability (`@webpob/codec`)**:
   - Encodes/decodes standard PoB sharing strings: `Base64URL -> zlib inflate (pako) -> XML`.
   - Auto-detects PoE 1 (`<PathOfBuilding>`) vs PoE 2 (`<PathOfBuilding2>` or PoE 2 classes/attributes).
   - Supports optional CORS proxy (`apps/cors-proxy`) for importing `pobb.in/<id>` and `pastebin.com/<id>` URLs directly in the browser.

## 2. Data Sync Pipeline (`scripts/sync-data`)

Because Path of Exile updates every league, `@webpob/data` is designed to ingest versioned JSON bundles generated by `scripts/sync-data` from:
- `PathOfBuildingCommunity/PathOfBuilding` (PoE 1 tree, gems, uniques, base items)
- `PathOfBuildingCommunity/PathOfBuilding-PoE2` (PoE 2 tree, gems, uniques, base items)
- Bilingual dictionaries (PoEDB / PoeCharm / community open-source translation tables)
